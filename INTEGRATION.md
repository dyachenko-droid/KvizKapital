# Запуск и атрибуция

`KvizApplication.onCreate()` инициализирует AppsFlyer 7.0.0 и OneSignal один раз
на процесс. Сессии AppsFlyer запускаются по `SessionReady` при доступной сети,
включая возвращение приложения из фона. Install Referrer 2.2 подключён отдельно.
Firebase настроен предоставленным `app/google-services.json`.

Первый запуск ждёт результат атрибуции не более 15 секунд. `Non-organic` выбирает
корневое поле `in_org` Realtime Database. После предварительного `Organic`
выполняется пятисекундное ожидание и уточнение через AppsFlyer GCD. При отсутствии
результата к 10-й секунде также выполняется уточнение; повторы и HTTP-запросы
ограничены общими 15 секундами. Неизвестный callback/ошибка не закрывают ожидание.
Если лимит истёк, установка считается органической и читается `org`.
Поздние ответы не переключают уже выбранный адрес.

Кампания сохраняется вместе с выбранным результатом: используются данные SDK
либо GCD, если уточнение GCD определило неорганическую установку. Предварительная
органическая кампания не заменяет кампанию выбранной неорганической атрибуции.

## Ссылки Firebase

На чтение Firebase отводится 8 секунд. Любая непустая строка, включая `12ук`,
`google.com` и строку из пробелов, считается полученной ссылкой. Формат, схема
и домен не проверяются; схема не дописывается, пробелы не обрезаются.
Отсутствующее поле, значение другого типа, пустая строка, ошибка или таймаут
ведут к стандартной privacy:
`https://dyachenko-droid.github.io/KvizKapital/privacy.html`.

Органическая строка `org` передаётся в WebView без изменений.
Только полученная строка `in_org` дополняется query-параметрами:

- `app_id` — AppsFlyer UID (`getAppsFlyerUID`), тот же, что используется в OneSignal.
- `sub1`, `sub2`, ... — части кампании, разделённой по `_`, в исходном порядке.
- Пустые части внутри/на концах кампании сохраняют позиции. При отсутствующей
  или пустой кампании добавляется только `app_id`.
- Значения новых параметров кодируются для query. Остальные query-параметры,
  исходная часть адреса и fragment сохраняются. Старые `app_id`, `subN` и `sub_N` заменяются.

Пример: кампания `one_two_three` и UID `af-123` преобразуют
`https://example.com/path?keep=1#page` в
`https://example.com/path?keep=1&app_id=af-123&sub1=one&sub2=two&sub3=three#page`.

Тестовый шаблон для `in_org`:

```text
https://example.com/?app_id={app_id}&sub1={sub1}&sub2={sub2}&sub3={sub3}
```

Имеющиеся параметры `app_id`/`subN`/`sub_N` заменяются фактическими значениями.
Количество `subN` определяется частями кампании; лишние параметры сабов удаляются.

Перед добавлением параметров заполняются плейсхолдеры `{name}` и `{{name}}`,
включая вариант с `%7B`/`%7D`. Для Meta-шаблона поддержаны соответствия:

| Плейсхолдер | Поля AppsFlyer (первое доступное) |
| --- | --- |
| `ad.id` | `ad_id`, `af_ad_id`, `adgroup_id` |
| `adset.id` | `adset_id`, `af_adset_id` |
| `campaign.id` | `campaign_id`, `af_c_id` |
| `ad.name` | `ad_name`, `af_ad`, `adgroup`, `adgroup_name`, `ad` |
| `adset.name` | `adset_name`, `adset`, `af_adset` |
| `campaign.name` | `campaign_name`, `campaign`, `c` |

Прямое совпадение имени плейсхолдера с ключом SDK имеет приоритет. Также
поддерживаются плейсхолдеры любых других скалярных полей ответа SDK/GCD,
`app_id`/`appsflyer_id` и номера сабов. Используются данные выбранной атрибуции;
органические поля не примешиваются к неорганическим. Недоступный плейсхолдер
остаётся без изменений: значения не угадываются. Подставляемые значения
кодируются для URL ровно один раз; остальные части ссылки не нормализуются.

Поля и варианты имён сверены с [документацией AppsFlyer](https://support.appsflyer.com/hc/en-us/articles/360000726098-Conversion-data-payloads-and-scenarios).

Итоговая ссылка сохраняется в SharedPreferences `startup`: `privacy_url`,
`remote_privacy = true`, `first_launch = false`. Она открывается без кнопки
принятия; следующие запуски используют готовую сохранённую строку без ожидания
AppsFlyer/Firebase и без повторного добавления параметров.

Стандартная privacy открывается с кнопкой «Принять». Только её нажатие завершает
первый запуск и открывает нативное приложение. Стандартная privacy не дополняется
параметрами. Совпадение удалённой ссылки со стандартной не меняет её происхождение:
она всё равно считается удалённой и открывается без кнопки.

## OneSignal

После инициализации AppsFlyer выполняется `OneSignal.login(appsFlyerUid)`:
`external_id` OneSignal равен AppsFlyer UID. Если UID/SDK ещё не готов, привязка
повторяется при готовности/успешной отправке сессии и получении атрибуции.
Это действует также для органических установок и запусков с сохранённой ссылкой.
Разрешение на уведомления запрашивается один раз при входе в нативное приложение
или удалённый WebView; при стандартной privacy — после принятия.

## WebView

Поддерживаются JavaScript, DOM storage, cookies и выбор файлов через системное
окно Android (`input type=file`), включая множественный выбор. Результат и отмена
передаются обратно в callback WebView. Несколько URI извлекаются из `ClipData`,
одиночный URI — из `Intent.data`. Резервный выбор — `ACTION_OPEN_DOCUMENT`.
При уничтожении WebView незавершённый выбор отменяется. HTTPS-сертификаты
проверяются стандартным механизмом WebView.

«Назад» возвращает на предыдущую страницу истории. При пустой истории нажатие
игнорируется: WebView и Activity остаются открытыми. Ошибка загрузки показывает
повтор загрузки и не заменяет сохранённую строку стандартной privacy.
Загрузка и WebView поддерживают поворот с `RotatingScreen`; игра остаётся
портретной. Диагностический журнал удалён; журнал старых сборок удаляется при
запуске обновления. Для отладки поверх WebView показано поле «Ссылка запуска WebView» с кнопкой
«Копировать». Оно содержит точную итоговую строку, переданную в `loadUrl`,
включая параметры и нераскрытые плейсхолдеры. Копируется вся строка, даже если
она не помещается в видимую часть поля. При редиректах поле сохраняет именно
ссылку запуска, чтобы можно было проверить подстановки и отправить её для анализа.

## Проверка

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

При обновлении APK уже сохранённый адрес остаётся в кэше. Чтобы проверить новое
получение `in_org` и параметры на тестовом устройстве, можно удалить только
настройки запуска, сохранив игровой прогресс:

```sh
adb shell am force-stop ru.kvizcap.quiz.app
adb shell run-as ru.kvizcap.quiz.app rm -f shared_prefs/startup.xml
```

Release-подпись применяется при наличии всех полей `keystore.properties`.
Debug APK работает без release-keystore. Проверка рекламной установки и
отображения external_id в кабинете выполняется на тестовом устройстве AppsFlyer
и в консоли OneSignal; тестовые push-сообщения автоматически не отправляются.
